# Инструкции для Fusion Common

## Контроль качества и команды разработки

Все команды выполняются из корня `fusion-common`:

- Обязательные проверки качества:
  - `uv run ruff check . --fix`
  - `PYTHONUTF8=1 uv run mypy . --pretty`
  - `uv run vulture`
  - `uv run pytest`

## Архитектурные правила

1. Пакет `fusion_common` содержит общее функциональное и сериализационное ядро (`Functional Core` на чистом `numpy` и `pydantic` без `pandas`), а также общие утилиты сплэш-экрана (`splash.py`) и сборки (`packaging.py`).
2. Контейнеры сырых измерений `.fus` и результатов анализа `.fusa` (схема v1.0 с граничной миграцией в `migration.py`) следуют принципу открытости/закрытости (OCP): датчики (`sensor`), компенсация холодного спая (`cjc`), калибровки (`calibration`) и метаданные канала (`metadata`, включая `exo_up`) привязаны к каждому отдельному каналу `ChannelDescriptor`.
3. Реестр загрузчиков `FORMAT_LOADERS` (`load_measurement`) обеспечивает 100%-ную обратную совместимость чтения со всеми архивными форматами (`.tda`, `.vtaz` v0.0 и v1.0, `.fus-mdt` v1.0, `.fus-fmdt` v1.0), тогда как запись новых данных выполняется только в `.fus` (сырые измерения) и `.fusa` (проекты анализа).
